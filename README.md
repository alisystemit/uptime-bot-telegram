# 📊 قالب مانیتورینگ سرور (Uptime)

ربات تلگرامی برای **پایش آپتایم سرور/سایت**: هر کاربر چند مانیتور می‌سازد، ربات هر
**۲۰ ثانیه** آن‌ها را بررسی می‌کند و قطعی/برقراری/کندی/انقضای گواهی را اعلام می‌کند.
به‌علاوه یک **صفحهٔ وب عمومی و قابل اشتراک‌گذاری** و **کار در گروه و کانال**.

---

## ✨ امکانات

| بخش | توضیح |
|---|---|
| 🔍 سه نوع بررسی | `HTTP/HTTPS` (کد وضعیت + زمان پاسخ)، `TCP` (اتصال پورت)، `ping` (ICMP) |
| ⏱ فاصلهٔ چک | پیش‌فرض ۲۰ ثانیه (قابل تغییر، کمینه ۱۰) |
| 📈 آپتایم | ۲۴ ساعت (دقیق)، ۷ و ۳۰ روز (تجمیع ساعتی) + نمودار میله‌ای ۳۰ روزه + نوار ۲۴ ساعته |
| 🐢 هشدار کندی | برای هر سایت «حد کندی» بگذارید؛ اگر پاسخ کندتر شد هشدار 🟠 می‌گیرید |
| 🔎 کلیدواژه | اگر متنی باید حتماً در پاسخ سایت باشد، تعریف کنید؛ نبودش = «قطع» |
| 🔔 اعلان | قطعی (بعد از N چک ناموفق) + برقراری + مدت توقف + هشدار کندی |
| 📜 رخدادها | هر قطعی/کندی با **علت، مدت و اوج زمان پاسخ** ثبت و قابل مرور |
| 🔐 گواهی SSL | تاریخ انقضا، صادرکننده، تطابق نام + هشدار خودکار پیش از انقضا |
| 🌐 انقضای دامنه | استعلام WHOIS (پشتیبانی از تاریخ شمسی) + هشدار پیش از انقضا |
| 👥 گروه و کانال | ربات داخل گروه: `/add`، `/list`، `/status`، اعلان قطعی در گروه، سقف جداگانه |
| 🤝 اشتراک‌گذاری | لینک عمومی کل حساب، **لینک تک‌سایت**، و **دعوت** (طرف مقابل اعلان را در چت خودش می‌گیرد) |
| 🌐 صفحهٔ وب | `status.php?u=` / `?g=` / `?s=` — تیره، RTL، نمودار، رخداد، خروجی CSV |
| ⏸ توقف موقت | توقف سراسری، هر کاربر، هر سایت (با آمار مدت توقف) |
| 👥 مدیریت کاربران | سقف کاربر، مسدودسازی، دسترسی، پیام همگانی، آمار کلی |
| 💳 اشتراک ویژه | سه روش: **کد فعال‌سازی** + **کارت به کارت دستی** + **درگاه آنلاین خودکار** |
| 🏦 درگاه‌های پرداخت | زرین‌پال، واریزا، کیوب‌پی، تتراپی، آبان گیت وی + **درگاه دلخواه** (بدون کدنویسی). تأیید وب‌هوکِ امضاشده، ضدتکرار، بررسی مبلغ |

## ⚙️ نصب

### ۱) ساخت با ربات‌ساز
از منوی ربات‌ساز «📊 مانیتورینگ سرور (Uptime)» را بزنید؛ توکن، ادمین، دامنه و
دیتابیس به‌صورت خودکار در `config.php` درج می‌شود.

### ۲) ساخت جدول‌ها
```
php table.php
```
یا در مرورگر (فقط با secret):
```
https://domain/bots/<slug>/table.php?secret=sha256(BOT_TOKEN + "_uptime_table_secret")
```
> جدول‌ها در صورت نبود، به‌صورت خودکار هم ساخته می‌شوند و ستون‌های جدید روی
> نصب‌های قدیمی با `ALTER TABLE` اضافه می‌شوند؛ `table.php` فقط نصبِ صریح است.

### ۳) وبهوک تلگرام
توسط ربات‌ساز تنظیم می‌شود. فرمول secret هدر:
```
sha256(BOT_TOKEN + "_uptime_webhook_secret")
```

## ⏰ راه‌اندازی کرون (مهم!)

بدون کرون، چک‌ها فقط هنگام بازدید صفحهٔ وضعیت انجام می‌شوند.

### روش ۱ — کرون سیستمی (پیشنهادی)
```cron
* * * * * php /مسیر/کامل/bots/<slug>/cron/checker.php
```
اسکریپت **هر بار ۳ نوبت با فاصلهٔ ۲۰ ثانیه** چک می‌کند؛ یعنی دقیقاً یک چک هر ۲۰ ثانیه،
بدون اینکه دو اجرای همزمان روی هم بیفتند (قفل `flock`).

### روش ۲ — کرون HTTP (هاست اشتراکی)
```cron
* * * * * curl -s "https://domain/bots/<slug>/cron/checker.php?secret=SHA256_TOKEN"
```
secret را از منوی ربات (⚙️ پنل مدیریت → ⏰ کرون) بگیرید.

### روش ۳ — دیمون دائمی
```bash
php /مسیر/bots/<slug>/cron/checker.php --daemon
```

### گزینه‌های checker.php
| گزینه | کار |
|---|---|
| `--once` | فقط یک راند و خروج (تست) |
| `--rounds=N` | تعداد نوبت‌ها (پیش‌فرض ۳) |
| `--daemon` | حلقهٔ بی‌نهایت با فاصلهٔ ثابت |
| `--json` | خروجی JSON |
| `--maintenance` | اجرای اجباری نگهداری (گواهی SSL، WHOIS دامنه، آمار زمان پاسخ) |
| `--selftest` | سلامت سیستم + پشتیبانی curl/openssl/whois |

> نگهداری به‌صورت خودکار هم داخل هر راند (هر ۳۰ دقیقه) اجرا می‌شود؛ کرون جدا لازم نیست.

## 👥 گروه و کانال

ربات را به گروه اضافه کنید. فقط **ادمین‌های گروه** می‌توانند مانیتور اضافه/حذف کنند.
سقف مانیتورهای گروه **جدا از سقف شخصی** است (`group_max_sites`).

| دستور | کار |
|---|---|
| `/add https://example.com نام` | افزودن مانیتور (یا فقط `/add` و بعد آدرس را بفرستید) |
| `/list` | فهرست مانیتورها با آپتایم |
| `/status #3` | جزئیات کامل یک مانیتور |
| `/check all` | بررسی فوری همه |
| `/pause all` • `/resume all` | توقف/ادامهٔ موقت |
| `/remove #3` | حذف (برای تأیید، دوباره همان دستور) |
| `/incidents` | تاریخچهٔ قطعی‌ها |
| `/page` | لینک صفحهٔ وضعیت عمومی گروه |
| `/notify off` | خاموش/روشن کردن اعلان گروه |
| `/domain example.ir` | پایش انقضای دامنه |
| `/cancel` | انصراف از عملیات نیمه‌کاره |

اعلان‌ها داخل گروه فرستاده می‌شوند و در صورت تمایل ادمین‌ها منشن می‌شوند
(`group_mention` = `none | admins | all`). برای کانال‌ها فقط دستورهای
`/list`، `/status`، `/incidents`، `/page` کار می‌کنند (کانال دکمه ندارد).

## 🤝 سه راه اشتراک‌گذاری

| روش | نتیجه |
|---|---|
| **🔗 صفحهٔ وضعیت من** | لینک عمومی همهٔ سایت‌های شما (فقط نمایش، بدون اعلان) |
| **🌐 لینک تک‌سایت** | صفحهٔ عمومی فقط یک مانیتور — مناسب امضای ایمیل/سایت |
| **👥 اشتراک‌گذاری** | لینک دعوت `t.me/<bot>?start=site_<token>`؛ طرف مقابل نقش «ناظر» یا «ناظر+مدیر» را می‌پذیرد و هشدارهای همان سایت را در **چت خصوصی خودش** می‌گیرد |

مانیتورهایی که دیگران به شما سپرده‌اند: منوی **«👥 مانیتورهای مشترک»**.

## 🌐 صفحهٔ وضعیت

| آدرس | محتوا |
|---|---|
| `status.php?u=<token>` | همهٔ مانیتورهای خصوصی یک کاربر |
| `status.php?g=<token>` | مانیتورهای یک گروه/کانال |
| `status.php?s=<token>` | فقط یک مانیتور |
| `+ &csv=1` | خروجی CSV آپتایم ساعتی ۳۰ روز اخیر |

- **بدون لاگین** و بدون نمایش اطلاعات خصوصی، `noindex`
- هر ۲۵ ثانیه با `api.php` تازه می‌شود و هر ۲٫۵ دقیقه شارژ کامل
- نمودار میله‌ای ۳۰ روزه، نوار ۲۴ ساعته، کمینه/میانگین/صدک۹۵/بیشینهٔ زمان پاسخ،
  کارت گواهی SSL و فهرست آخرین رخدادها
- لینک عمومی هر مانیتور با دکمهٔ «🔄 تغییر لینک» باطل می‌شود

## 🔐 گواهی SSL و دامنه

- **گواهی**: خواندن گواهی HTTPS با `stream_socket_client('ssl://…')` و
  `openssl_x509_parse` — بدون وابستگی بیرونی. برای هر سایت `https://` هر
  `ssl_interval` (پیش‌فرض ۱ ساعت) خوانده می‌شود و اگر کمتر از `ssl_warn_days`
  روز مانده باشد هشدار داده می‌شود (فقط یک‌بار برای هر تاریخ انقضا).
- **دامنه**: استعلام WHOIS روی پورت ۴۳. اگر هاست پورت ۴۳ را بسته باشد، نتیجه
  «نامشخص» می‌شود و ربات هیچ خطایی نمی‌بیند. تاریخ‌های شمسی هم پشتیبانی می‌شوند.
- بررسی دستی گواهی: دکمهٔ «🔐 گواهی SSL» در منوی هر سایت.

## 🏆 رنکینگ و امتیازدهی

همهٔ منطق امتیاز در **یک ماژول** جمع شده: `lib/ranking.php`. موتور چک بعد از هر
چکِ موفق `Ranking::onCheck()` را صدا می‌زند و بقیهٔ بخش‌ها فقط نمایش‌اند.

| امتیاز | چه‌وقت داده می‌شود | کلید نگه‌بان |
|---|---|---|
| امتیاز روزانه | یک‌بار در هر روز (UTC)، به هر کاربرِ دارای سایتِ سالم | `rank_day_<uid>_<تاریخ>` |
| پاداش آپتایم | یک‌بار در هر ساعت، برای هر سایتِ بالا | `rank_up_<site>_<تاریخ‌ساعت>` |

- **سطوح**: هر ۱۰۰ امتیاز یک سطح بالاتر، بیشینه ۱۰ سطح (`user_rank`).
- **اتمیک**: همهٔ افزایش‌ها با یک `UPDATE` ریاضی انجام می‌شود، پس دو اجرای
  همزمان امتیاز گم نمی‌کنند.
- **بدون `N+1`**: کلیدهای جایزه از کشِ درون‌پروسه‌ای تنظیمات رد می‌شوند؛
  کوئریِ اضافه فقط در اولین چکِ هر روز/ساعت می‌خورد.
- کلیدهای کهنه در نگهداریِ هر ۳۰ دقیقه پاک می‌شوند تا جدول `settings` رشد نکند.

**نمای کاربر** — دستور `/rank` یا دکمهٔ «📊 رنکینگ»:

| دکمه | کار |
|---|---|
| 🏆 جدول امتیاز | ۲۰ کاربر برتر با مدال، سطح و ساعت آپتایم |
| 🏅 رتبهٔ من | امتیاز، سطح، نوار پیشرفت، وضعیت سایت‌ها و جایزهٔ امروز |
| 💡 نحوهٔ امتیازدهی | توضیح قوانین امتیاز به زبان ساده |
| ⚙️ تنظیمات رنکینگ | فقط برای مدیر |

**دستورهای مدیر** (از همان منو):

- `🎁 جایزهٔ دستی` → با پیامِ `شناسه مقدار` (مثلاً `123456 50`)؛ امتیازِ منفی هم مجاز است.
- `🔄 بازنشانی فصل` → صفرکردن امتیاز همه و پاک‌کردن کلیدهای جایزهٔ امروز.

## 💳 درگاه‌های پرداخت

اشتراک ویژه می‌تواند **خودکار** از طریق درگاه بانکی/کارت‌به‌کارت فعال شود.
مسیر کاربر:

```
🛒 اشتراک ویژه → 💳 پرداخت آنلاین → انتخاب درگاه → دریافت لینک/شمارهٔ کارت
                                                  → 🔄 بررسی پرداخت (دستی)
```

### تنظیم (پنل مدیریت → ⚙️ → 🏦 درگاه‌های پرداخت)

| درگاه | کلید | واحد مبلغ | تأیید نهایی | مستندات |
|---|---|---|---|---|
| 💳 زرین‌پال | کد Merchant (۳۶ کاراکتری) | ریال | `verify.json` | `api.zarinpal.com/pg/v4` |
| 🏦 واریزا | API Key + **Webhook Secret** | تومان | وب‌هوکِ امضاشده | `variza.ir/developers` |
| 💳 کیوب‌پی | API Token (`@cubepy_bot` ← 🔗 پنل من) | ریال | `verify-payment.php` | `github.com/cubepy/cubepay-doc` |
| 🪙 تتراپی | ApiKey (پنل فروشنده tetra98.ir) | ریال | `api/verify` | `tetra98.ir/docs` |
| 🏦 آبان گیت وی | توکن `live_…` یا `test_…` | ریال | `POST /invoices/{id}/verify` | `abangateway.ir/docs/api` |
| 🔧 درگاه دلخواه | دلخواه | ریال | از پنل تنظیم می‌شود | — |

برای هر درگاه: **کلید را وارد کنید → 🧪 تست اتصال → 🟢 فعال کردن**.
کلیدها فقط در جدول `pay_gateway` می‌مانند و در هیچ پیامی نمایش داده نمی‌شوند.

### آدرس بازگشت / وب‌هوک

در پنل هر درگاه این آدرس را ثبت کنید:

```
https://DOMAIN/pay.php?g=CODE
```

مثال واریزا: `https://example.com/pay.php?g=variza`

### 🔧 درگاه دلخواه (بدون مستندات عمومی)

برای سرویس‌هایی مثل تون‌پی، اطلس‌پی، ترونادو و بلوپال که **مستندات عمومی API
منتشر نکرده‌اند**، درگاه «دلخواه» مسیرها و نام فیلدها را از شما می‌گیرد و نیازی به
دست‌زدن به کد نیست. دکمهٔ 🧩 در همان صفحه، این JSON را می‌گیرد:

```json
{
  "create_path": "/api/pay",
  "verify_path": "/api/verify",
  "ref_path": "id",
  "url_path": "pay_url",
  "status_path": "status",
  "ok_values": ["paid", "ok"],
  "ref_field": "id",
  "field_map": { "amount": "amount", "order_id": "order", "callback_url": "callback" },
  "auth_style": "bearer",
  "sign_algo": "sha256"
}
```

| کلید | کار |
|---|---|
| `create_path` | مسیر ساخت فاکتور (الزامی) |
| `verify_path` | مسیر تأیید؛ اگر خالی باشد **فقط وب‌هوک ملاک است** |
| `ref_path` / `url_path` | نام فیلد شناسه و لینک پرداخت در پاسخ |
| `status_path` / `ok_values` | فیلد وضعیت و مقدارهایی که یعنی «پرداخت شد» |
| `field_map` | نگاشت نام فیلد شما → یکی از `amount`، `order`، `callback`، `desc`، `user`، `email` |
| `auth_style` | `bearer` \| `header` \| `query` \| `body` |
| `sign_algo` | اگر وب‌هوک شما امضا دارد (مثلاً `sha256`)، این را بگذارید تا بررسی شود |
| `expires_in` (واریزا) | `30m`/`1h`/`1d`/`never` |
| `ttl_minutes` (کیوب‌پی) | مهلت پرداخت |
| `expiry_minutes` (آبان) | مهلت پرداخت |
| `pay_mode` (تتراپی) | `bot` (لینک تلگرام) یا `web` |
| `card_last_4` (واریزا) | `random` \| `variza` \| چهار رقم کارت |

### 🔐 چرا امن است

1. **مبلغ همیشه از دیتابیس خودمان می‌آید**، نه از callback. اگر درگاه مبلغِ
   متفاوتی برگرداند، فاکتور تأیید نمی‌شود.
2. **هیچ callbackای مبنای نهایی نیست.** بعد از هر وب‌هوک، `verify` صدا زده
   می‌شود و فقط پاسخ آن تصمیم می‌گیرد (همان چیزی که مستندات کیوب‌پی الزامی کرده).
3. **وب‌هوک امضاشده** (واریزا: `HMAC-SHA256` روی بدنهٔ خام + `X-Delivery-Id`
   برای ضدتکرار) بدون امضای درست هیچ اتفاقی نمی‌افتد.
4. **فعال‌سازی اشتراک idempotent است**؛ تأیید دوباره هیچ سودی نمی‌دهد و تمدید
   زنجیره‌ای از تاریخ انقضای فعلی حساب می‌شود.
5. هدرها روی **nginx** هم خوانده می‌شوند (`getallheaders()` روی nginx وجود ندارد).
6. سقف ۳ فاکتور باز برای هر کاربر در هر درگاه.

## 🧰 عیب‌یابی

| مشکل | بررسی |
|---|---|
| «کرون اجرا نمی‌شود» | `--selftest` را بزنید (curl/openssl/whois را هم گزارش می‌کند) |
| `403 Forbidden` | secret نادرست است یا توکن در `config.php` عوض شده |
| `DB ERROR` | اطلاعات `db` در `config.php` را بررسی کنید |
| چک‌ها انجام نمی‌شوند | `pause_all` روشن نباشد؛ سایت/کاربر متوقف نباشد |
| ping کار نمی‌کند | هاست باید اجازهٔ `exec`/`proc_open` بدهد؛ در غیر این صورت به TCP:443 می‌افتد |
| گواهی SSL «نامشخص» | `openssl` و پشتیبانی TLS روی هاست را بررسی کنید |
| WHOIS جواب نمی‌دهد | پورت ۴۳ روی هاست بسته است (نتیجه «نامشخص» ثبت می‌شود) |
| خطای PHP | `logs/` را ببینید (`uptimeLog`) |
| درگاه «۴۰۰ امضا نامعتبر» می‌دهد | `Webhook Secret` در پنل درگاه با مقدار پنل مدیریت شما یکی نیست، یا آدرس بازگشت اشتباه است |
| درگاه فاکتور می‌سازد ولی تأیید نمی‌شود | لاگ را ببینید: `pay webhook bad signature … body_len=… sig_len=…` — اگر `sig_len=0` باشد هدر وب‌هوک توسط وب‌سرور/پراکسی حذف شده |
| «درگاه غیرفعال است» | در پنل، کلید را وارد و 🟢 فعال کردن را بزنید (بدون کلید، روشن‌کردن ممکن نیست) |
| «مبلغ پرداختی مطابقت ندارد» | مشتری مبلغ دقیق نمایش‌داده‌شده در پیام فاکتور را واریز نکرده است |

## 📌 نکته‌ها

- برای PHP 8.1 به بالا تست شده است (MySQL 5.7/8، MariaDB).
- همهٔ کوئری‌ها **prepared** می‌شوند؛ ورودی کاربر هرگز داخل SQL نمی‌نشیند.
- اجرای همزمان دو راند با `flock` روی `logs/round.lock` و `logs/checker.lock` غیرممکن است.
- زمان ذخیره‌سازی همه‌جا **UTC** است؛ نمایش ساعت محلی با `tz_offset` کانفیگ انجام می‌شود.
- شناسهٔ گروه/کانال در تلگرام **منفی** است؛ در کد از `Group::isGroupChat()`
  (مخالف صفر) استفاده کنید، نه `> 0`.
- `logs/` و `lib/` با `.htaccess` مسدودند؛ `config.php` هم در سطح `bots/` مسدود است.
