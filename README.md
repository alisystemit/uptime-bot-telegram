# 📊 قالب مانیتورینگ سرور (Uptime)

قالب ربات تلگرامی برای **پایش آپتایم سرور/سایت**: هر کاربر تا ۵ سایت ثبت می‌کند،
ربات هر **۲۰ ثانیه** وضعیت آن‌ها را بررسی می‌کند و قطعی/برقراری را اعلام می‌کند.
به‌علاوه یک **صفحهٔ وب عمومی و قابل اشتراک‌گذاری** برای هر کاربر.

---

## ✨ امکانات

| بخش | توضیح |
|---|---|
| 🔍 سه نوع بررسی | `HTTP/HTTPS` (کد وضعیت + زمان پاسخ)، `TCP` (اتصال پورت)، `ping` (ICMP) |
| ⏱ فاصلهٔ چک | پیش‌فرض ۲۰ ثانیه (قابل تغییر، کمینه ۱۰) |
| 📈 آپتایم | ۲۴ ساعت (دقیق)، ۷ و ۳۰ روز (تجمیع ساعتی) + نوار رنگی ۶۰ چک اخیر |
| 🔔 اعلان | پیام قطعی (بعد از N چک ناموفق پیاپی) و برقراری + مدت توقف |
| 🌐 صفحهٔ وب | `status.php?u=<token>` — تیره، RTL، ریسپانسیو، بروزرسانی خودکار |
| ⏸ توقف موقت | توقف سراسری، توقف هر کاربر، توقف هر سایت (با آمار مدت توقف) |
| 👥 مدیریت کاربران | سقف کاربر، مسدودسازی، دسترسی، پیام همگانی، آمار کلی |
| 💳 اشتراک ویژه | سه روش: **کد فعال‌سازی** + **زرین‌پال** + **کارت به کارت** |
| 🎟 کدها | ساخت کد با تعداد مصرف و مدت دلخواه |

## 🗂 ساختار فایل‌ها

```
uptime/
├── config.php          کانفیگ (توکن، ادمین، دیتابیس، دامنه) — هنگام ساخت پر می‌شود
├── index.php           وبهوک تلگرام (با secret هدر)
├── table.php           ساخت/به‌روزرسانی جدول‌ها (با secret)
├── status.php          صفحهٔ وضعیت عمومی هر کاربر
├── api.php             JSON همان صفحه (برای بروزرسانی زنده)
├── botapi.php          کلاینت سبک Telegram Bot API
├── .htaccess           مسدودسازی لاگ/قفل/lib — نقطه‌های ورود باز می‌مانند
├── lib/
│   ├── bootstrap.php   بوت‌استرپ مشترک همهٔ endpointها
│   ├── db.php          لایهٔ PDO + مایگریشن (idempotent)
│   ├── util.php        توابع کمکی فارسی/اعتبارسنجی
│   ├── monitor.php     موتور چک (probe + round + اعلان + prune)
│   ├── stats.php       آپتایم و گزارش‌ها
│   └── bot.php         منوها و منطق ربات
├── cron/
│   ├── _guard.php      گارد دسترسی وب به کرون
│   └── checker.php     اسکریپت چک (تکی / ۳ نوبتی / دیمون)
└── vendor/autoload.php استاب autoload (بدون وابستگی Composer)
```

## ⚙️ نصب

### ۱) ساخت با ربات‌ساز
از منوی ربات‌ساز «📊 مانیتورینگ سرور (Uptime)» را بزنید؛ توکن، ادمین، دامنه و
دیتابیس به‌صورت خودکار در `config.php` درج می‌شود.

### ۲) ساخت جدول‌ها
```
php table.php
```
یا در مرورگر (فقط با secret):
```
https://domain/bots/<slug>/table.php?secret=sha256(BOT_TOKEN + "_uptime_table_secret")
```
> جدول‌ها در صورت نبود، به‌صورت خودکار هم ساخته می‌شوند؛ `table.php` فقط نصبِ صریح است.

### ۳) وبهوک تلگرام
توسط ربات‌ساز تنظیم می‌شود. فرمول secret هدر:
```
sha256(BOT_TOKEN + "_uptime_webhook_secret")
```

## ⏰ راه‌اندازی کرون (مهم!)

بدون کرون، چک‌ها فقط هنگام بازدید صفحهٔ وضعیت انجام می‌شوند.

### روش ۱ — کرون سیستمی (پیشنهادی)
```cron
* * * * * php /مسیر/کامل/bots/<slug>/cron/checker.php
```
اسکریپت **هر بار ۳ نوبت با فاصلهٔ ۲۰ ثانیه** چک می‌کند؛ یعنی دقیقاً یک چک هر ۲۰ ثانیه،
بدون اینکه دو اجرای همزمان روی هم بیفتند (قفل `flock`).

### روش ۲ — کرون HTTP (هاست اشتراکی)
```cron
* * * * * curl -s "https://domain/bots/<slug>/cron/checker.php?secret=SHA256_TOKEN"
```
secret را از منوی ربات (⚙️ پنل مدیریت → ⏰ کرون) بگیرید.

### روش ۳ — دیمون دائمی
```bash
php /مسیر/bots/<slug>/cron/checker.php --daemon
```
برای سرورهای شخصی بدون crontab؛ با `nohup` یا systemd اجرا کنید.

### گزینه‌های checker.php
| گزینه | کار |
|---|---|
| `--once` | فقط یک راند و خروج (تست) |
| `--rounds=N` | تعداد نوبت‌ها (پیش‌فرض ۳) |
| `--daemon` | حلقهٔ بی‌نهایت با فاصلهٔ ثابت |
| `--json` | خروجی JSON |
| `--selftest` | فقط سلامت سیستم، بدون چک سایت‌ها |

## 🌐 صفحهٔ وضعیت

آدرس هر کاربر داخل ربات (منوی «🔗 صفحهٔ وضعیت من») ساخته می‌شود:
```
https://domain/bots/<slug>/status.php?u=<share_token>
```
- **بدون لاگین** و بدون نمایش اطلاعات خصوصی
- هر ۲۵ ثانیه با `api.php` تازه می‌شود و هر ۲٫۵ دقیقه شارژ کامل
- قابل اشتراک‌گذاری در شبکه‌های اجتماعی؛ `noindex`
- با دکمهٔ «🔄 عوض کردن لینک» داخل ربات می‌توان توکن را باطل کرد

|---|---|

| `table.php` | `sha256(TOKEN + "_uptime_table_secret")` |

## 🗄 جدول‌ها

| جدول | نقش |
|---|---|
| `user` | کاربران (**نام و ستون‌ها عمداً با ربات‌ساز یکی است** تا پیام همگانی/آمار کار کند) |
| `site` | سایت‌های تحت نظر + وضعیت لحظه‌ای |
| `check_log` | فقط ۲۴ ساعت اخیر (نوار رنگی و آپتایم روزانه) |
| `uptime_hour` | تجمیع ساعتی برای ۷/۳۰ روز |
| `settings` | کلید/مقدار تنظیمات |
| `codes` | کدهای فعال‌سازی |
| `events` | رویدادها (قطعی، توقف، پرداخت) برای آمار |
| `payments` | درخواست‌های پرداخت |
| `seen_update` | جلوگیری از پردازش تکراری آپدیت تلگرام |

> `check_log` با `maybePrune()` بیش از ۲۴ ساعت نگه داشته نمی‌شود تا دیتابیس رشد نکند.

## 🧰 عیب‌یابی

| مشکل | بررسی |
|---|---|
| «کرون اجرا نمی‌شود» | آیا کرون هر دقیقه اجرا می‌شود؟ `--selftest` را بزنید |
| `403 Forbidden` | secret نادرست است یا توکن در `config.php` عوض شده |
| `DB ERROR` | اطلاعات `db` در `config.php` را بررسی کنید |
| چک‌ها انجام نمی‌شوند | `pause_all` روشن نباشد؛ سایت/کاربر متوقف نباشد |
| ping کار نمی‌کند | هاست باید اجازهٔ `exec`/`proc_open` بدهد؛ در غیر این صورت به TCP:443 می‌افتد |
| خطای PHP | `logs/` را ببینید (`uptimeLog`) |

## 📌 نکته‌ها

- برای PHP 8.1 به بالا تست شده است.
- همهٔ کوئری‌ها **prepared** می‌شوند؛ ورودی کاربر هرگز داخل SQL نمی‌نشیند.
- اجرای همزمان دو راند با `flock` روی `logs/round.lock` و `logs/checker.lock` غیرممکن است.
- `logs/` و `lib/` با `.htaccess` مسدودند؛ `config.php` هم در سطح `bots/` مسدود است.
